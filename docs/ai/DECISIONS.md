# Decisions

### D-046 · 2026-11-10 · Claude Opus 5.5 (Claude Code)
**Decision:** The Research Lab (only) may give a fund a brain from another vendor through OpenRouter. `config/models.ts` carries `provider: 'anthropic' | 'openrouter'` per model; `server/providers/openaiCompat.ts` is a fetch-based OpenAI-compatible decision loop with the same `LoopResult` contract as the Anthropic loop (retries 429 and 5xx; prices on the requested model id; never sends `effort`; a `length` finish with tool calls ends as `max_tokens`; empty tool arguments are `{}`). `labBrain` routes by the model's provider and applies the same budget reserve and settle for both. `configuredProviders(env)` reads which of `ANTHROPIC_API_KEY` and `OPENROUTER_API_KEY` are set; errors are "Model brains need a provider key on the server." with no key and "No key on the server for provider <p>." with only some. `AnthropicModelId` keeps the live world on Anthropic only, checked at compile time.
**Context:** The paper's brains comparison is stronger with models from more than one vendor, but the live world's budget ledger, caching and effort handling are built around Anthropic.
**Reasoning:** One narrow adapter behind the existing loop contract avoids a vendor SDK per provider; keeping the live world on a compile-time Anthropic-only type means a cross-vendor model cannot reach unattended spending.
**Rejected:** Cross-vendor models in the live world (unattended spend on an unverified path); one SDK per vendor (dependency and approval cost); a proxy service (new dependency and moving part).
**Tradeoff accepted:** Cross-vendor arms are not fully comparable with Anthropic arms. (1) Effort/reasoning settings are not sent to OpenRouter, because no parameter works the same across vendors. (2) The prompt cache is billed at multiplier 1. (3) Pricing uses the requested id even when OpenRouter serves a dated variant. (4) OpenRouter routing may change which upstream provider serves a model. Any cross-vendor result must be reported with these four caveats.
**Pre-registration:** `paper/PREREGISTRATION.md` is NOT amended. H1 stays Anthropic-only as pre-registered; the cross-vendor arms are not in the pre-registered study, so no amendment is triggered. If they are ever added to a study, amend before those runs.
**Revisit if:** a cross-vendor arm joins the pre-registered study, OpenRouter's response shape changes, or a vendor needs a reasoning parameter to be comparable.

### D-045 · 2026-11-10 · Claude Opus 5.5 (Claude Code)
**Decision:** The Stage 10 study is pre-registered by git: `paper/PREREGISTRATION.md` and `paper/study/*.json` are committed (`9b18473`; Amendment 1 in `adc4636`) before any run, and deviations are logged in the paper appendix. `npm run study:run` enforces it: it refuses unless the prereg is tracked and the prereg and `paper/study/` have no diff against HEAD and no untracked files; it validates every spec (`studyPlan.checkStudyPlan`) and prints the worst-case dry-run total ($793.92 over 42 experiments: a worst-case estimate under the `DECISION_PROMPT_TOKENS_ESTIMATE` = 3000 prompt-token assumption, not a bound and not spend; the hard cap is each file's `budgetUsd`, summing to $804, checked against spend plus the call's worst-case estimate before every model call); it submits only with `--confirm` and `LAB_ADMIN_TOKEN`. Submission is resumable by name: a file whose name already has a queued, running or done experiment is skipped (`pendingSubmissions`), using the additive public filter `GET /lab/experiments?name=` (exact name; absent means no filter). Failed experiments may be resubmitted under the same name; the exporter counts only the newest `done` per name (highest id), says which older ones it ignored, and lists every failed experiment with its error in `paper/data/failed.csv`.
**Context:** A pre-registration only means something if the specs cannot change after the data is seen, and a $794 ceiling needs a safe retry path after a partial failure.
**Reasoning:** The commit is the timestamp, so the tool checks git instead of trusting the operator; resuming by name prevents paying twice or double-counting seeds.
**Rejected:** A manual checklist for the commit rule (unenforced); resubmitting everything on retry (double spend); deleting failed rows (loses the failure record).
**Tradeoff accepted:** The git check does not prove the commit is the intended one; the lookup adds one GET per spec file; duplicates stay in the DB and are ignored at export.
**Revisit if:** the study is run from a machine without the repo, or a second provider (Phase 5) needs its own plan checks.

### D-044 · 2026-11-10 · Claude Opus 5.5 (Claude Code)
**Decision:** Five behavioural metrics are computed per fund per run (`packages/engine/src/behaviour.ts`) and reported per arm as the mean over seeds with a bootstrap 95% CI. `actionEntropy`: Shannon entropy of the counts of {buy, short, close, hold} over all decisions, divided by log2(4); 0 = one action only, 1 = uniform; null with no decisions. `riskCompliance`: share of non-hold proposals that `enforceRiskLimit` left unchanged (`clamped === false`); a proposal the limit refused (turned into hold) counts as non-compliant; null with no non-hold proposals. `repeatedErrorRate`: of the closes with `realizedPnL < 0` on ticker T, the share followed by a new open on T in the same direction within `BEHAVIOUR_REPEAT_WINDOW_TICKS` = 50 ticks; null with no losing closes. `shockDeRisk`: mean over shocks of `grossPct(t) - grossPct(t + 30)`, a shock being an event with `abs(priceImpactPercent) >= 5` (`BEHAVIOUR_SHOCK_MIN_IMPACT_PCT`, `BEHAVIOUR_SHOCK_WINDOW_TICKS` = 30), `grossPct` = sum of absolute position notional divided by NAV times 100 sampled at the nav cadence; positive = cut exposure; shocks whose window runs past the end are skipped; null with no usable shocks. `tradeRate`: trades divided by decisions; null with no decisions. Memory usefulness is the H2 contrast itself (return versus `memory=none`), not a per-run metric.
**Context:** The VISION names behavioural diversity, strategy consistency, repeated errors, reaction to shocks and risk adaptation; the study needs definitions fixed before any data (Gate G1).
**Reasoning:** Each metric uses data the sim already has (decision trail, clamp flag, gross series, event log), so digests are unchanged and the gross series is dropped in `summarize` and never reaches `resultJson`. Pinning windows and thresholds as constants keeps the definitions auditable.
**Rejected:** Counting only clamped (not refused) proposals as non-compliant (hides the strongest limit violations); a per-run memory-usefulness metric (that is a between-arm contrast).
**Tradeoff accepted:** Metrics are per fund-run summaries, so rare events (shocks, losing closes) give null for many runs and wide CIs; old experiments lack `behaviour` and show an em dash.
**Revisit if:** the pre-registered study shows most cells null (lengthen runs or lower the shock threshold before data, not after).

### D-043 · 2026-11-10 · Claude Opus 5.5 (Claude Code)
**Decision:** `memory` is a one-variable experiment axis with four modes (`MemoryMode` in `packages/engine/src/simMemory.ts`): `none`, `episodic`, `reflective`, `full`. `ArmConfig.memory` is the base setting (default `none`); the server validates it ("memory must be one of none, episodic, reflective, full."). After each tick's decisions are applied, `updateSimMemory` records episodes and reflections into `SimFund.memory`, using the same rules as the live world's `rememberDecision` (`memory.ts`). Only model-backed funds hold or read memory; policy funds get none.
**Context:** H2 asks whether memory changes model behaviour and returns; the live world already has agent memory (D-026) but experiment worlds had none.
**Reasoning:** Policy funds never read memory, so writing it for them would be dead state, and policy-only digests stay byte-identical. Reusing the `memory.ts` rules keeps experiment memory the same thing the live funds have.
**Rejected:** Memory for policy funds (no effect, risks digest drift); a boolean on/off (cannot separate episodic from reflective contributions).
**Tradeoff accepted:** Memory lives in RAM per run and is not persisted beyond the stored decisions; a policy-only memory experiment is valid but all arms are identical (the UI says "Memory only affects model brains.").
**Revisit if:** a memory arm needs cross-run carry-over, or the keyed smoke run (Gate G5) shows memory prompts blowing the token budget.

### D-042 · 2026-11-09 · Claude Opus 5.5 (Claude Code)
**Decision:** (Final-review fixes I1–I4.) **Spend:** the runner (`server/experiments.ts`) owns the `ExperimentBudget` and passes it to `runExperimentSpec`; after every `llm` or `fallback` decision it writes `Experiment.costUsd` = spend so far, and any failure (not only `BudgetExhausted`) writes the final spend. `requeueInterrupted` never touches `costUsd`, so a restart keeps the persisted spend; decisions are still batched per run, so a crash can lose the current run's decision rows but not its recorded spend. **Payload:** `GET /lab/experiments/:id` no longer returns per-run `events` (the replay route serves them); stored `resultJson` is unchanged. `GET /lab/leaderboard` is cached in memory, keyed on (count, max id) of `done` `brains` rows from one `aggregate`. **Replay:** `findRun`/`buildRunReplay` return null (route 404) for a run without navs or events; `RunReplay.tsx` also guards missing arrays. **Leaderboard:** each row carries `fallbackRate` = Σ fallback / Σ (llm + fallback) over its samples (shown in TIMELINE); a model run with zero `llm` decisions is not a sample of that model; a model row is `insufficient` below 5 paired samples (Policy: below 5 runs).
**Context:** Final whole-branch review: paid spend had no record after a restart or non-budget failure; the public, polled leaderboard re-parsed multi-MB blobs on every request; a legacy replay link blanked the app; outage runs (all fallback) were ranked as the model, and a row ranked on one pair was not flagged.
**Reasoning:** One small update per paid call is negligible next to the call, and no settled call's spend can go unrecorded. Done rows are immutable and only added, so (count, max id) identifies the board. A run with no model decision measured the policy; counting pairs matches what the board ranks by.
**Rejected:** Persisting spend once per run (loses up to a run's spend on a crash); flushing decisions per paid call (more writes, not needed for the spend record); shrinking stored events (data change, out of scope); a fallback-rate threshold above zero `llm` (arbitrary without live data).
**Tradeoff accepted:** Runs with some but not all fallbacks still count; readers judge them by the shown `fallbackRate`, which covers only the counted samples. The cache is per process and would serve a stale board if a done row were ever deleted and replaced with the same count and max id.
**Revisit if:** the keyed smoke run shows high partial fallback rates (add a threshold), or done experiments become deletable.

### D-041 · 2026-11-09 · Claude Opus 5.5 (Claude Code)
**Decision:** The public leaderboard (`GET /lab/leaderboard` → `{leaderboard}`, pure core `server/leaderboardCore.ts`) is built from every `done` experiment whose variable is `brains` (route query `status: 'done', variable: 'brains'`); no hand-picking. Samples come only from subject funds: funds whose brain is a model in some arm. Each model result is paired by fund and seed with the same experiment's all-policy baseline arm only; mixed arms are never a partner. A row is `insufficient` when n < 5 (`MIN_RUNS`): listed, not evidence. Run cost is attributed to the subject fund (exact while an arm has one model fund). Legacy or malformed `resultJson` rows are skipped. The TIMELINE view shows the leaderboard plus run cards for the newest `CHRONICLE_MAX_EXPERIMENTS` = 10 done experiments (legacy runs without navs skipped; brains looked up by arm label). Run replay (`#/timeline/<id>/<arm>/<seed>`, `RunReplay.tsx`) plots exact `navTicks` (raw nav point k is at tick 3·(k+1)), syncs a decision feed to the cursor, plays at 150 ms per point and shows the manifest hashes.
**Context:** Phase 1 produced paired results per experiment; readers need one place that aggregates them without cherry-picking and a way to watch a single run.
**Reasoning:** Pairing only against the all-policy baseline keeps every row a comparison against the same reference, so rows are comparable across experiments; a mixed arm would confound two brains. The n ≥ 5 flag stops tiny samples reading as findings. Exact `navTicks` avoid a guessed x axis.
**Rejected:** Pairing against any arm (confounded); hiding insufficient rows (silent selection); splitting cost across funds in an arm (no data to split on); a stored leaderboard table (derivable, would go stale).
**Tradeoff accepted:** ~~Every leaderboard request loads all qualifying `resultJson` rows, uncached.~~ Cached and made fallback-aware by D-042. Replay limits: no `hashchange` routing (the hash routes only on a full page load); decisions after the last nav tick are hidden; digest shows '—' for experiments outside the newest chronicle set; feed capped at `EXPERIMENT_REPLAY_MAX_DECISIONS` = 2000. Cost attribution is inexact once an arm has several model funds.
**Revisit if:** the number of brains experiments makes the unpaged query slow (cache or store aggregates), or arms gain several model funds (per-fund cost metering).

### D-040 · 2026-11-09 · Claude Sonnet 5.5 (Claude Code)
**Decision:** Experiment statistics live in a pure `packages/engine/src/stats.ts`: a percentile bootstrap 95% CI of the mean (2000 resamples, seeded `mulberry32`, so reruns reproduce), an exact two-sided binomial sign test on paired seed wins (ties dropped from n), and Holm step-down correction across every comparison of an experiment. `compareArms` reports per fund and arm: mean total return with CI, paired Δ vs the baseline arm with CI, wins, raw and Holm-adjusted sign-test p, fallback rate and mean cost per run.
**Context:** The lab shows paired per-seed results; with at most 10 seeds the numbers need uncertainty and a multiple-comparison guard before anyone quotes them.
**Reasoning:** A bootstrap makes no normality assumption for a handful of seeds; the exact sign test is valid at n≤10 where a t-test or normal approximation is not; Holm controls family-wise error without Bonferroni's loss of power and needs no independence assumption. All three are small, deterministic and unit-tested by hand-checked values.
**Rejected:** t-test (normality unjustified at n≤10); BCa bootstrap (needs more resamples and a jackknife for no visible gain at this n); Bonferroni (too conservative); a stats dependency (AGENTS.md: none without approval).
**Tradeoff accepted:** Percentile bootstrap is rough below ~10 pairs and the CI of 2 pairs is nearly degenerate; the sign test ignores effect size. Known minors (deferred): upper percentile index `floor(q*iters)` is one rank high versus the `ceil(q*iters)-1` convention; `0.5**n` underflows for n>1074 (unreachable at ≤10 seeds).
**Revisit if:** seed limits rise (then add BCa or a Wilcoxon signed-rank test), or reports need effect-size-aware tests.

### D-039 · 2026-11-09 · Claude Sonnet 5.5 (Claude Code)
**Decision:** An experiment with any model brain must declare `budgetUsd` (≤ `EXPERIMENT_MAX_BUDGET_USD` = 25, `config/game.ts`). Each model call first reserves its worst-case cost; the experiment stops with `BudgetExhausted` before a call that could exceed the limit, so spend never exceeds the budget by more than the difference between a call's estimate and its actual cost. The experiment is then `failed` with `budget exhausted at $X.XX`, `costUsd` set to the spend, and decisions already written are kept. Creating a model-brain experiment without `ANTHROPIC_API_KEY` is rejected with 400 `Model brains need a provider key on the server.`. A model-backed experiment (`Experiment.hasModelBrains`) interrupted by a restart is marked `failed` with `interrupted by restart` instead of being re-queued; policy-only ones still re-queue. `POST /lab/experiments?dryRun=1` (same token) validates and returns the worst-case `estimateUsd` without storing.
**Context:** Policy runs are free and deterministic, so re-queueing after a restart was harmless. A model run pays the provider again on every rerun and is not reproducible.
**Reasoning:** A hard cap enforced before the call is the only bound that holds when the provider cost is only known afterwards; the dry run lets the form show the worst case without duplicating pricing in the browser. Failing an interrupted paid run keeps the spend visible rather than silently doubling it.
**Rejected:** Re-queue model runs (double spend); resume from stored decisions (not deterministic, needs run-level checkpoints); estimating cost client-side (engine duplication); a soft warning instead of a cap.
**Tradeoff accepted:** The estimate uses `ceil(ticks/every)` decision slots per fund (the true worst case for offset slots), so it is slightly high; the reconsider gate makes real spend lower. ~~Failures other than budget exhaustion record `costUsd` 0 even if the provider was paid for earlier calls.~~ Fixed by D-042: every failure and every restart keeps the spend. Live $/decision is UNMEASURED.
**Revisit if:** runs become long enough that a restart losing a paid run hurts (checkpoint per run), or per-user budgets are needed.

### D-038 · 2026-11-09 · Claude Sonnet 5.5 (Claude Code)
**Decision:** The engine's experiment world loop is split into advance, decide and apply (`advanceTick`, `applyDecisions`). The synchronous `simulateWorld` keeps policy brains; a new `simulateWorldAsync` takes an injected `DecideFn` so a fund's brain can be a model. `ArmConfig.brains?: Record<string, FundBrain>` is optional (absent means all policy) and `'brains'` is a fifth experiment variable. The server supplies the model-backed `DecideFn` in `server/labBrain.ts` (`makeExperimentDecide`): same reconsider gate, prompts and tool loop as the live world, falling back to the fund's policy with `source: 'fallback'` when the loop returns no decision. Every decision of every run (policy, llm, fallback) is persisted to `ExperimentDecision`, which a public per-run replay endpoint reads.
**Context:** Experiments could only compare policies. The research goal needs model-vs-policy and model-vs-model arms on paired seeds, replayable.
**Reasoning:** Injecting the LLM call keeps the engine pure (no SDK import) and lets tests drive a stub provider. Keeping the sync path means policy-only digests stay byte-identical (pinned before the refactor and compared after; a test also checks that the runner's async-with-sink path reproduces the sync result). Making `brains` optional leaves stored specs and their `configHash` unchanged.
**Rejected:** One async loop for everything (changes policy-only timing and risks digest drift); calling the provider inside the engine (breaks purity); a required `brains` field (rewrites old manifests).
**Tradeoff accepted:** Policy-only runs in the runner now go through the async path to record decisions, which is slower than the sync loop (digests verified identical). `ExperimentDecision` stores every policy decision too: up to ticks × funds × arms × seeds rows, written with one `createMany` per run (relies on Prisma's internal chunking; deferred). `resultJson` also stores each run's full event list.
**Revisit if:** decision volume makes the table large (add retention or chunking), or a second provider is added (the `CreateMessage` injection is already provider-agnostic).

### D-035 · 2026-11-02 · Claude Opus 5.5 (Claude Code)
**Decision:** Liquidation is judged on the whole fund. `checkLiquidation` now flags a fund when its equity (NAV = cash + longs − shorts, at market) falls below `MAINTENANCE_MARGIN_RATE` (25%) of its shorts' current value. Before, only each short's posted margin plus its own P&L counted, so free cash never backed a short. Initial margin is unchanged: 50% of a new short is still locked out of `availableCash`. `LIQUIDATION_RULE_VERSION = 2` is in `config/game.ts`, so experiment manifests from the old rule hash differently. The client's `liquidationAt` (the NAV at which the fund dies) is now 25% of the short book.
**Context:** User decision 2026-11-02 after D-034. Under the old rule a $10M fund with one $2M short up ~20% was liquidated while holding ~75% of NAV in cash; the old `liquidationAt` showed such a fund dying at a NAV of $9.5M (a 5% drawdown).
**Reasoning:** A broker issues a margin call before force-closing, and a fund with free cash posts it; equity vs maintenance on the whole account is the standard (Reg-T style) test. Measured on seeded 2000-tick experiment worlds (seeds 1–40) with the D-034 policies: 0 liquidations in 240 aggressive/quant runs (seeds 1–40 × Director none/rule), versus 1 of 180 on seeds 11–40 under the old rule. Mean returns barely move (seeds 11–40: HALDEN −0.5% / −0.3%, CROWN −5.4% / −7.2%). A fully levered short book (policies' 1.5× gross ceiling) now dies at a ~33% adverse move instead of ~20% per short.
**Rejected:** Auto-depositing free cash into a short's `marginReserved` on a call (same outcome, more mutable state and a second source of truth for collateral); keeping the per-short rule and only fixing the display (the rule itself was the unrealistic part).
**Tradeoff accepted:** Liquidation is now much rarer; a fund mostly dies only after losing most of its equity. Results and liquidation counts from experiments run before this change are not comparable with new ones (the manifest's `worldConstantsHash` changed). D-034's volatility cap stays, as a loss limiter rather than a survival rule.
**Revisit if:** longs become marginable (then longs need their own maintenance requirement), or funds should be able to die faster for drama (raise `MAINTENANCE_MARGIN_RATE`, not the old rule).

### D-034 · 2026-11-02 · Claude Opus 5.5 (Claude Code)
**Decision:** The policy funds keep their characters but stop shorting into margin calls. (1) No policy shorts a name with per-tick volatility above `POLICY_MAX_SHORT_VOLATILITY = 0.025` (HELX, CURA, ORBL, NOVA are now long-only for policies). (2) `exitOnTarget` cuts the worst stopped-out position before it banks any winner — this also changes STERLING & VALE (cautious), which shares it. (3) The quant policy has a stop, `POLICY_QUANT_STOP_LOSS = 0.12`, checked before its flow exits.
**Context:** In experiment worlds HALDEN WHITMORE and CROWN MERIDIAN were margin-liquidated in 38 of 40 seeded 2000-tick runs (10 seeds × Director none/rule). Every death was one short ~20% underwater while the fund held most of its NAV in cash: a lone short is liquidated at a ~20% adverse move (50% initial vs 25% maintenance margin), policies act every 10 ticks, and HELX's 10-tick sigma is ~11% (uniform per-tick noise, sd = volatility/sqrt(3)) before event shocks, so a 20% move between two decisions is routine. The rest were slow grinds the quant (no stop) never cut, or a stop skipped because a winner was banked first.
**Reasoning:** Measured with `simulateWorld` before/after. Seeds 1–10: liquidations 38 → 0. Held-out seeds 11–40: 1 of 180 aggressive/quant runs liquidated (a 2.3-sigma TITAN run-up under the Director). Mean 2000-tick return on seeds 11–40 (none / rule Director): HALDEN −0.5% / −0.5%, CROWN −5.4% / −7.4%, STERLING +0.9% / +3.0%. A quant stop of 0.08 or 0.10 survived too but churned (CROWN −17% / −12% on seeds 1–10); 0.15 let liquidations back in.
**Rejected:** Changing the liquidation rule so free cash tops up the margin account (realistic, but a world rule that also changes model-driven funds and every past experiment — a separate decision for the user); smaller short sizes (the liquidation distance is the same fraction whatever the size); deciding more often (changes cadence, cost and the live world's rhythm).
**Tradeoff accepted:** The policies are less "aggressive" in the most volatile names, and CROWN still loses money on average — this fixes survival, not alpha. Model-driven funds are not constrained (enforceRiskLimit is unchanged), so an LLM can still short HELX.
**Revisit if:** the margin rule changes (free cash posted as collateral), the decision cadence changes, or ticker volatilities are recalibrated.

### D-033 · 2026-11-02 · Claude Opus 5.5 (Claude Code)
**Decision:** The Research Lab has its own authorization boundary. `GET /lab/experiments` and `GET /lab/experiments/:id` are public observation. `POST /lab/experiments` needs `Authorization: Bearer <LAB_ADMIN_TOKEN>`: unset token → 503 (lab writes disabled), missing/wrong bearer → 401, then request validation → 400. The token is compared as SHA-256 digests with `timingSafeEqual`. The client sends it with the create request only; it is never stored in the store or browser storage.
**Context:** VISION §13 — "Public observation and privileged experiment configuration must have separate authorization boundaries."
**Reasoning:** A single shared secret is the smallest boundary that keeps experiment creation (which consumes server CPU) privileged without user accounts. Disabled-by-default means a fresh deploy cannot be used to queue work.
**Rejected:** Reusing `/auth` JWT accounts (the observer client no longer has accounts); IP allow-lists (brittle behind proxies); no auth (VISION violation).
**Tradeoff accepted:** One token for every admin, no per-user audit; CORS is still `*`, so the token's secrecy is the whole boundary.
**Revisit if:** more than one operator needs distinct permissions, or model-backed experiments add spend (then also a per-experiment budget).

### D-032 · 2026-11-02 · Claude Opus 5.5 (Claude Code)
